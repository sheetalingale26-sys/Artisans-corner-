## 1. Executive Summary & Platform Mission

Mass manufactured commerce depersonalizes goods, drives quality downward, and extracts excessive take-rates (often 20% to 45%) from independent creators. **Artisan’s Corner** fundamentally recalibrates craft commerce:

* **Fair 5% Commission Model:** Makers retain a guaranteed **95% of every dollar** generated by their studio.
* **Ancestral Authenticity:** Dedicated craft categories including *Ceramics & Pottery*, *Woodwork & Carving*, *Jewelry & Metals*, *Textiles & Fiber Art*, *Glassblowing*, and *Leathercraft*.
* **Immersive 3D Artifact Exploration:** Proprietary client-side Three.js interactive rendering engine allowing collectors to inspect studio pieces with realistic PBR lighting, rotating viewpoints, wireframes, and materials analysis.
* **Frictionless Seller Classification:** Streamlined onboarding requiring only essential classification details upfront (Shop Name, Discipline, City), allowing instant dashboard access with progressive profile completion.
* **Institutional Governance:** Multi-tenant RBAC separating Buyer marketplaces, Artisan Studio management, and Super Administrator audit consoles.

## 3. Enterprise Software Architecture

The platform adheres to strict separation of concerns, decoupling presentation logic from business domain rules, routing coordinators, and security filters:

```
┌────────────────────────────────────────────────────────────────────────┐
│                        PRESENTATION LAYER (VIEW)                       │
│      React 19 Components • TailwindCSS 4 • Lucide Icons • Motion       │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ User Events & Triggers
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        MIDDLEWARE & SECURITY GATE                      │
│   • Auth Verification (Firebase Auth Token)                            │
│   • RBAC Guard (Admin Whitelist / Seller Verification Filter)          │
│   • Input Sanitization & Error Handling Interceptors                   │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ Authorized Requests
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                       CONTROLLERS (BUSINESS LOGIC)                     │
│   • AppContext Controller (Session, Catalog, Orders, Ledger)           │
│   • SellerOnboarding Controller (Instant Classification Engine)        │
│   • PayoutEngine Controller (95% Net / 5% Commission Calculator)       │
│   • 3D Studio Controller (WebGL Camera, Lighting, Materials)           │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ Data Operations & Schema Binding
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                        MODELS (DOMAIN CONTRACTS)                       │
│    User Schema • SellerProfile Schema • Product Schema • Order Schema  │
│             Payout Schema • CommissionRecord • SellerApplication       │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ Persistence Sync
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   PERSISTENCE & INFRASTRUCTURE LAYER                   │
│      Cloud Firestore (NoSQL) • LocalStorage Cache • Firebase Hosting   │
└────────────────────────────────────────────────────────────────────────┘
```

### Architectural Separation Details:

* **Controllers (`src/context/AppContext.tsx`, `src/stores/`):** Orchestrate all state transitions, financial calculations, Firebase Auth lifecycle events, and Firestore synchronization. View components never perform raw mutations directly.
* **Models (`src/types/index.ts`):** Single source of truth containing immutable TypeScript domain interfaces (`User`, `SellerProfile`, `Product`, `Order`, `Review`, `Payout`, `SellerApplication`).
* **Routes (`src/App.tsx`):** Declarative state-driven routing coordinating deep links and tabs (`marketplace`, `studio`, `orders`, `seller-dashboard`, `admin-dashboard`, `wishlist`, `login`, `register`).
* **Middleware & Security (`src/context/AppContext.tsx`, Firebase Rules):** Intercepts unauthorized navigation, evaluates admin whitelist arrays (`AUTHORIZED_ADMIN_EMAILS`), enforces active status against suspended accounts, and guards seller routes.

## 7. Cloud Infrastructure & Firebase Ecosystem

The application leverages Google Cloud and Firebase infrastructure for scale, low-latency delivery, and authentication security:

* **Firebase Authentication:** Single sign-on supporting Google OAuth popup workflows and hardened email/password credentials with auto-profile synchronization.
* **Cloud Firestore:** Document database syncing every user state mutation under `users/{uid}` with merge writes:
  ```typescript
  await setDoc(doc(db, 'users', user.id), {
    uid: user.id,
    name: user.name,
    email: user.email,
    role: user.role,
    isSellerApproved: user.isSellerApproved,
    sellerProfileId: user.sellerProfileId,
    lastLoginAt: new Date().toISOString(),
    updatedAt: new Date().toISOString()
  }, { merge: true });
  ```
* **Firebase Hosting:** Global Content Delivery Network (CDN) with automatic SSL certificates, HTTP/2 multiplexing, Single Page Application (SPA) wildcard rewrites, and 1-year immutable caching for static assets.
* **Firebase Analytics:** Client-side event tracking initialized conditionally in compliant browser environments.

## 8. Security Engineering, RBAC & Governance

* **Strict Role-Based Access Control (RBAC):** Users are classified into `buyer`, `seller`, or `admin`. Route access is evaluated on every tab transition.
* **Administrator Whitelist Validation:** Platform administrative actions require explicit inclusion in `AUTHORIZED_ADMIN_EMAILS`:
  ```typescript
  export const AUTHORIZED_ADMIN_EMAILS = [
    'admin@artisanscorner.org',
    'marcus.vance@artisanscorner.org',
    'director@artisanscorner.org',
    'sheetalingale26@gmail.com',
    'sheetal3@gmail.com'
  ];
  ```
* **Account Freezing:** Suspended accounts are barred from authentication with explicit error responses.
* **Data Sanitization:** Trims email whitespace, validates minimum password thresholds, and strips HTML from user inputs.

## 9. Financial Architecture & Fair 5% Commission Engine

Artisan’s Corner implements transparent, ethical fee mechanics:

$$\text{Net Maker Revenue} = \text{Gross Product Sale} \times 0.95$$

$$\text{Platform Maintenance Fee} = \text{Gross Product Sale} \times 0.05$$

* **Makers Keep 95%:** No hidden listing fees, payment processing markups, or algorithmic ad bidding.
* **Disbursement Ledger:** When an artisan seller requests a payout, the controller verifies available balance, records the transaction in `payouts`, deducts the balance, and logs the last 4 digits of their ACH routing account.

## 10. State Management & Data Persistence Strategy

The system utilizes a dual-tier state architecture ensuring continuous availability and zero data loss:

1. **Reactive App Context (`AppContext.tsx`):**
   * Acts as the primary application controller.
   * Dispatches state updates across all connected view components.
   * Auto-synchronizes critical collections (`users`, `sellers`, `products`, `orders`, `payouts`) to `localStorage` on every change.
2. **Progressive Onboarding Store (`sellerOnboardingStore.ts`):**
   * Powered by Zustand with persistent local storage.
   * Automatically saves drafts of artisan applications so users never lose entered information during multi-session setup.

## 13. Build Pipeline, Performance & CI/CD Deployment

### Production Compilation
